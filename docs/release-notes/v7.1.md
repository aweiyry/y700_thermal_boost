## 🧩 模块 V7.1 — 配置热重载（改配置不用重启）

**支持机型**：三代 `TB321FU` · 四代 `TB322FC` · 五代 `TB323FU`

### 本次重点：改配置**不用重启**了

之前每次切换 `ZONE_MODE` / `ENABLE_THERMAL_BYPASS` / 伪装温度都要重启一次，做 A/B 对比非常折腾。
V7.1 起模块**每 5 秒重读一次 `config.prop`**，改完保存即生效，并写进运行日志：

```
/data/local/tmp/y700_thermal_boost/runtime.log
配置热重载: 温控=1->0 温区模式=1->2 杀温控=0->0 伪装(CHG/BATT/USB/AP)=25000/28000/25000/30000 采样=5s 杀间隔=60s 日志=1
  -> 已关闭绕过: 伪装温度已清除, 温区已恢复
```

- 关闭绕过（`ENABLE_THERMAL_BYPASS=0`）时会**清掉伪装温度、恢复被禁用的温区、并把 CCL 还原为解锁前的值**，
  保证「关掉模块 = 回到原始状态」，便于做 A/B 对照
- 所有配置项增加**合法性校验**：写错的值会被忽略并回退默认值，不会把模块搞坏
- 重新开启绕过后，若正在充电会**立刻补一次伪装**，不等下一轮

### 🧪 新增：深度定位测试脚本 `y700_full_diag.sh`

针对「模块全部生效但充电只有 ~10W」这类问题，比旧脚本更完整，**自带 A/B 对比（靠热重载，无需重启）**：

| 章节 | 内容 |
|---|---|
| 【3】充电链路全节点 | **全量 dump 所有 power_supply 节点**（uevent + 关键属性）：PDO 协商结果、`current_max`、`charge_type`、`sw_jeita_enabled`、`step_charging_enabled`、`input_current_limited` 等 |
| 【4】平台决策证据 | `dmesg` 里的充电/PD/PPS/JEITA/AICL 日志、`dumpsys thermalservice` 限流状态、`dumpsys battery`、系统里与充电相关的 settings |
| 【5】温区与热源全景 | 列出**全部**温区并标出哪些被模块伪装；再列「高温热源 TOP8」——找出模块没覆盖、却可能是平台限流依据的传感器（如 `front_temp/back_temp/user_temp/pmih010x_tz`） |
| 【6】历史充电峰值 | 汇总最近 10 次充电的峰值功率/开始电量/协议 + 最近一次的分阶段数据，直接回答「这台机器到底有没有快充过」 |
| 【7】**自动 A/B** | 依次跑：A 基线 → B 仅伪装(`ZONE_MODE=2`) → C 完全关闭模块 → D 还原；每组采样 40 秒，自动汇总功率/温度/CCL 并给出判读 |
| 【9】结论 | 自动判断「与模块无关 / 模块有副作用 / 建议改用 ZONE_MODE=2」 |

```bash
# 完整版(含自动 A/B, 约 4 分钟; 需模块 V7.1+)
su -c "sh y700_full_diag.sh"

# 只抓快照, 不做 A/B (约 40 秒, V7.0 也能用)
su -c "sh y700_full_diag.sh --no-ab"
```

### 🔧 本次实机/离线验证

- 配置热重载用**本地假 sysfs 仿真**跑通：`ZONE_MODE` 1↔2 切换、`bypass` 开↔关、伪装温度变更、
  以及非法值（`ZONE_MODE=abc` / `SAMPLE_INTERVAL=xyz`）兜底，模块均按预期收敛且进程稳定
- 温区禁用清单开机重建、`KILL_THERMAL` 开关、运行时日志沿用 V7.0 已验证逻辑

### 🧪 充电被锁 10W 的 A/B 顺序（V7.1 起无需重启）

| 步骤 | 操作 | 判读 |
|---|---|---|
| 0 | 先跑 `y700_full_diag.sh`，看【3】【4】【6】节证据 | 定位是充电器/线材还是平台策略 |
| 1 | `ENABLE_THERMAL_BYPASS=0`（保存即可生效） | 功率恢复 → 模块副作用；不变 → **与模块无关** |
| 2 | `ZONE_MODE=2` | 规避平台保护性小电流回落 |
| 3 | `KILL_THERMAL=1` | 排除温控服务反复重启干扰 |

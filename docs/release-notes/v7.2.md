## 🧩 模块 V7.2 — 修复双实例 + 深度定位脚本升级（含「干预实验」）

**支持机型**：三代 `TB321FU` · 四代 `TB322FC` · 五代 `TB323FU`

### 1️⃣ 修复：pid 回绕导致的双实例（社区报告实测发现）

四代用户的报告里出现 **2 个模块实例并存**（V7.0 的 pid 21429 与 V7.1 的 pid 2004 同时运行）。
根因：单实例判定原本用「**pid 更小 = 启动更早**」，而 pid 会回绕（21429 先启动，但 2004 更小），
导致新实例误判自己最早而启动。

- 现改为比较 `/proc/<pid>/stat` 的 **starttime**（真实启动时刻，jiffies），这才是可靠的先后依据
- 遗留的旧实例仍需**重启一次**清掉；重启后不会再出现双实例

### 2️⃣ 充电日志新增「开始屏幕」行

记录每次充电开始时的亮屏/息屏状态 —— 部分联想机型**亮屏会压充电电流**，
有了这一行就能直接对比「同样电量下，息屏是不是更快」。

### 3️⃣ 深度定位脚本 `y700_full_diag.sh` 升级

**新增【7.5】干预实验** —— 既然 A/B 已能证明「限流在不在模块」，这一节就逐个去试**平台侧的开关**，
看哪一项能真正把电流放出来（每项限时施加、事后自动撤销）：

| 实验 | 做法 | 若功率明显上升说明 |
|---|---|---|
| **T1** 息屏 | 息屏 35 秒（需加参数 `--screen-test`） | 这台机器**亮屏限流**，息屏充就快 |
| **T2** 关闭 ZUI 电池保养 | `battery_maintenance_on=0` + `zui_battery_extreme_enabled=0` | **ZUI「电池保养/智能充电」在限流**，去系统设置里永久关掉 |
| **T3** 提高输入电流上限 | 写 `usb/input_current_limit=3A` | 该节点可解锁，**可以加进模块功能** |
| **T4** 解锁 CCL | 写 `charge_control_limit=上限` | CCL 解锁在这台机器上有效 |

同时修复：
- `grep -vE '^\s*$'` 在 toybox grep 下不支持 `\s` → 配置内容打印为空，改用 `[[:space:]]`
- 输入上限功率**单位算错**（223800W 那种离谱值）→ 改用 µA×µV/1e12，且电压优先取 ucsi 节点
  （`usb/voltage_now` 在 PPS 下不可信）
- 【3】节新增：`battery/power_now`、`power_avg` 电量计口径功率 + **充电器契约能力**
  （`usb/current_max`、`voltage_max`、ucsi 节点的 `CURRENT_MAX/CURRENT_NOW/VOLTAGE_NOW`）

```bash
su -c "sh y700_full_diag.sh"                  # 完整(快照+证据+自动A/B+干预实验)
su -c "sh y700_full_diag.sh --screen-test"    # 额外测「息屏是否更快」(会短暂黑屏)
su -c "sh y700_full_diag.sh --no-ab"          # 只抓快照(约 40 秒)
```

### 📊 四代实测数据（用户远程报告，已证实与模块无关）

| 组 | 配置 | 平均功率 |
|---|---|---|
| A | 模块正常 | 11.06W |
| B | 仅伪装 | 13.28W |
| **C** | **模块完全关闭** | **13.34W** |

- 关模块与开模块基本一致 → **瓶颈不在模块**
- 历史记录：17% 电量那次充了 92 分钟，**峰值也只有 12.8W**
- dmesg 实证：`VBUS=[1.13A, 9.59V]`（实际只抽 11W），而充电器契约是
  `ucsi CURRENT_MAX=3.24A @ 9.48V`（约 30W）→ **设备只用了 1/3**
- 平台侧线索：`battery_maintenance_on=1`、`charge_control_start/end_threshold=70/80`、
  `zui_battery_extreme_enabled=1` → 怀疑 **ZUI 电池保养/智能充电** 或**亮屏限流**（T1/T2 实验验证）

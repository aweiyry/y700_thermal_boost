## 🧩 模块 V7.0 — 兼容性开关 + 修掉一个「假功能」

**支持机型**：三代 `TB321FU` · 四代 `TB322FC` · 五代 `TB323FU`

### 1️⃣ 新增兼容性开关（针对 issue #1「Y700 四代充电被锁 10W」）

| 配置项 | 取值 | 说明 |
|---|---|---|
| `ZONE_MODE` | `1`(默认) / `2` | `1`=禁用温区 + 伪装温度（性能释放最好）<br>`2`=**仅伪装温度**，温区保持 `mode=enabled` |
| `KILL_THERMAL` | `0`(默认) / `1` | `1`=周期击杀温控进程（每 `KILL_INTERVAL` 秒一次）；`0`=交给平台自管 |

**背景**：部分四代/五代机型在温区被 `disabled` 后，平台会**回落到保护性小电流**（实测约 10W，约 5V/2A）。
此时改用 `ZONE_MODE=2` 即可绕开。`ZONE_MODE=2` 时模块会把此前禁用的温区**重新写回 `enabled`**；
启动日志与充电日志都会打印当前生效模式：`模块版本: V7.0 (温区模式 1)`。

### 2️⃣ 修掉一个长期存在的「假功能」：杀温控进程从未生效

排查中发现 **V6.x 的「杀温控进程」其实一直是失效的**：

- 原实现用 `ps -A -o PID,NAME` 匹配 `*thermal*`，但**模块运行上下文里 `ps` 列不出其他进程名**
  （实测温控命中数恒为 0，而同一时刻用 `/proc` 扫描可稳定命中 2 个）→ 旧代码一直在静默空转
- V7.0 改用 `/proc/<pid>/cmdline` 扫描（与单实例检测同源）并排除自身，**实测已能命中**：
  `已杀温控进程: /vendor/bin/thermal-engine-v2 (pid …)`
- 由于该功能本版才真正生效，`KILL_THERMAL` **默认设为 `0`**，避免升级后行为被悄悄改变；需要的人设为 `1`

### 3️⃣ 顺带修掉实现问题

- **温区禁用清单开机重建**：温区编号每次开机可能变化，旧实现让 `disabled_zones.list` 无限累积脏数据
  （实测堆到上百条），且每 5 秒对每个温区 `grep` 一次；现改为开机校验（存在 + 当前确实是 `disabled`）后重建
- **新增运行日志** `/data/local/tmp/y700_thermal_boost/runtime.log`（保留最近 200 行）：记录启动参数、生效模式、
  杀温控的每一次动作（成功 / 被 SELinux 拦截），排障时优先看它（`log_me` 的 logcat 输出容易被刷掉）

### 🧪 充电被锁 10W 的 A/B 排查顺序

| 步骤 | 操作 | 判读 |
|---|---|---|
| 0 | 先跑诊断脚本确认温区伪装 / 单实例 / CCL 正常 | 异常 → 是模块问题，发报告 |
| 1 | `ENABLE_THERMAL_BYPASS=0` + 重启，同电量同温度再充 | 恢复 → 模块副作用；仍 10W → **与模块无关** |
| 2 | `ZONE_MODE=2` + 重启 | 规避平台保护性小电流回落 |
| 3 | `KILL_THERMAL=1` + 重启（开启周期杀温控） | 排除温控服务反复重启对充电策略的干扰 |

> 每步只改一个变量，且保持电量/温度接近，否则结论不可信。

## 🔧 本次实机验证（Y700 五代 TB323FU / KernelSU / Android 16）

| 验证项 | 结果 |
|---|---|
| 默认（`ZONE_MODE=1`, `KILL_THERMAL=0`） | 11/11 目标温区 `disabled` + 伪装温度生效，单实例运行 ✅ |
| `ZONE_MODE=2` + 重启 | 充电温区恢复 `mode=enabled`、伪装温度仍生效 ✅ |
| 切回 `ZONE_MODE=1` + 重启 | 温区重新 `disabled`，无残留 ✅ |
| `KILL_THERMAL=1` | `runtime.log` 记录命中并杀掉 thermal HAL / thermal-engine，init 数秒内重新拉起 ✅ |
| `KILL_THERMAL=0` | 温控进程 pid 在 70 秒采样窗口内保持不变（未被模块干预）✅ |
| 温区禁用清单 | 开机校验重建，10 条无重复（旧实现会堆到上百条）✅ |
| 诊断脚本全流程 | 10 节全部跑通，无假警报（含本次修正的 `mode` 可写性误报）✅ |

## 🔍 诊断脚本（作为 Release 附件直发）

**`y700_diag.sh`** —— 一键检测模块全部作用点 + 动态监控，下载即可用：

```bash
su -c "sh /sdcard/y700_diag.sh"        # 默认采样 60 秒
su -c "sh /sdcard/y700_diag.sh 120"    # 自定义采样时长
```

报告输出到 `/sdcard/Y700模块诊断_<时间>.txt`，共 10 节：环境 / 模块完整性 / 实例 / 温区逐项对比 /
写入实测 / 温控进程 / 充电与节点 / 限流分析 / 动态监控 / 自动结论。

本版同步更新：
- 识别 `ZONE_MODE` / `KILL_THERMAL`，温区对比表**按当前模式判读**（模式 2 下「未禁用」不再算异常）
- `mode` 可写性改按**写入是否被拒绝**判定（模块运行中每 5 秒会重置温区，旧的回读判定会误报「不可写」）
- 第 6 节温控进程：用 `/proc` 复核 + 摘录 `runtime.log` 里的杀温控记录
- 抑制了 SELinux 拦截时的 `Permission denied` 噪声输出
